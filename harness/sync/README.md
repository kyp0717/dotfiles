# Keeping the two machines in sync

You alternate between two computers, **woodlawn** and **linden**, swapping
roughly weekly. Both run the same two harnesses:

- **dsh** (DeepSeek Harness) with the Kimi Code integration
- **pi**, with voice input via the official `pi-voice-stt` npm extension and
  the local whisper speech-to-text server as its transcription backend

The repo is the single source of truth. Nothing on a machine is a copy of a
repo file by hand. Config is regenerated by scripts, and anything that must
stay per machine is listed below so you never sync the wrong thing.

See [`MACHINES.md`](MACHINES.md) for the per-machine facts (hardware, tuning,
hostnames).

---

## The mental model

**The repo is the recipe; the scripts bake the config.**

```
git clone ai-harness
  →  npm run dsh:setup          # writes ALL dsh harness config
  →  npm run skills:install     # repo skills → ~/.dsh/skills
  →  npm run dsh:kimi-login     # per-machine Kimi subscription credential
  →  cargo build --release      # pi whisper server (see its SETUP.md)
```

Every step is idempotent. Re-running on a drifted machine brings it back.

## Fresh machine: full setup

Prerequisites: Node.js ≥ 18, git, Rust toolchain (for the whisper server),
and optionally the Kimi Code CLI (`kimi`) which powers `subagent_kimi`.

### dsh

1. Boot the pinned harness once so the profile initializes:
   `npx --yes @deepseek-ai/dsh@0.1.1-rc.2 --profile web`, then stop it.
2. `git clone git@github.com:kyp0717/ai-harness.git && cd ai-harness`
3. `npm run dsh:setup` (writes the ACP bridge from `dsh/vendor/`, the profile
   patch, the `kimi` preset, and `settings.yaml` with default model
   `kimi-coding/k3` plus the NVIDIA free-tier profile)
4. `npm run dsh:kimi-login` (device-code login, per machine)
5. `npm run skills:install` (vendored skills → `~/.dsh/skills/`)
6. GUI → Settings → API keys: add `NVIDIA_API_KEY`, `DEEPSEEK_API_KEY`, and
   any pay-as-you-go Kimi keys you use
7. Restart the GUI and run the parity check below

Full detail and troubleshooting: [`dsh/docs/SETUP.md`](../dsh/docs/SETUP.md).

### pi

1. Install pi itself (see pi's own docs) and sign in / set provider keys.
2. Build and start the whisper server via `run.sh` (it picks the `cpu` or
   `cuda` backend by hostname; on linden the CUDA toolkit must be installed
   first), then register it as a systemd user service. Full procedure:
   [`pi/speech-to-text/rust-whisper-server/SETUP.md`](../pi/speech-to-text/rust-whisper-server/SETUP.md).
3. On machines with fewer cores than woodlawn, set `WHISPER_THREADS` in the
   systemd unit (see `MACHINES.md`).
4. Install the voice client extension:
   `sudo apt install -y ffmpeg` then `pi install npm:pi-voice-stt`, and write
   `~/.pi/agent/stt.json` with provider type `local`. Full procedure:
   [`pi/speech-to-text/pi-voice-stt-setup.md`](../pi/speech-to-text/pi-voice-stt-setup.md).

Skills need no install step for pi: sessions inside this repo auto-discover
`.agents/skills/`.

## Weekly swap routine

Before leaving machine A:

```bash
cd ai-harness
git add -A && git commit -m "harness config update"   # if anything changed
git push
```

On machine B before working:

```bash
cd ai-harness && git pull
npm run dsh:setup          # re-applies dsh config, idempotent
npm run skills:install     # refreshes ~/.dsh/skills
# whisper server: only rebuild if pi/speech-to-text changed
# restart both harnesses, then run the parity check below
```

`npm run dsh:kimi-login` only when a token dies. The error "OAuth refresh
failed … invalid grant" means re-login.

While working on either machine: encode harness changes in this repo (script
or docs) and commit. Hand edits to `~/.dsh` do not sync. Secrets stay local:
a new API key on B is added in the GUI on B, and again on A when you return.

## Synced vs per machine

| Item | Synced via repo? | Where it lives |
|---|---|---|
| dsh setup/login/bridge scripts | yes | `dsh/scripts/` |
| Pinned dsh vendor tarballs | yes | `dsh/vendor/` |
| Vendored skills (pstack-strict, 30) | yes | `.agents/skills/` |
| dsh profile patch, `kimi` preset, `settings.yaml` | yes, written by `npm run dsh:setup` | `~/.dsh/…` |
| dsh user-root skills | yes, via `npm run skills:install` | `~/.dsh/skills/` |
| pi whisper server source + setup doc | yes | `pi/speech-to-text/rust-whisper-server/` |
| pi-voice-stt extension install (npm package) | no, per machine via `pi install` | `~/.pi/agent/npm/node_modules/pi-voice-stt`, settings.json |
| pi-voice-stt config (`stt.json`, provider `local`) | no, per machine | `~/.pi/agent/stt.json` |
| Whisper build (`target/`), logs | no, rebuilt per machine | `pi/speech-to-text/rust-whisper-server/` (gitignored) |
| Whisper model `ggml-base.bin` (147 MB) | no, too big for git; rsync or re-download (checksum in its SETUP.md) | same dir |
| Whisper systemd unit | content is in its SETUP.md; installed per machine | `~/.config/systemd/user/` |
| Kimi CLI login / OAuth / sessions | **per machine** | `~/.kimi-code/` |
| dsh subscription credential | **per machine**, via `npm run dsh:kimi-login` | `~/.dsh/.credentials.yaml` |
| Provider API keys | **per machine**, GUI settings | harness settings storage |

**Rule:** never copy `~/.kimi-code/`, credentials files, or API keys between
machines, and never commit them. Each machine authenticates once on its own.

## Known-good dsh snapshot (what "identical" means)

Verified on woodlawn (2026-08-28):

- **Profile** `~/.dsh/profiles/web/cordis.patch.yml`: `subagent-kimi` provider
  row and `agent-presets.default: kimi`, in the loader `- insert:` / override
  forms.
- **Preset** `~/.dsh/.agent-presets/kimi/agent.cordis.yml`: the shipped
  `standard` preset plus the `tool-subagent-kimi` row.
- **Packages** in `~/.dsh/profiles/node_modules/`:
  `@deepseek-ai/dsh-subagent-acp@0.1.1-rc.2` and
  `@agentclientprotocol/sdk@0.25.1` (tarball SHA-256s in git history).
- **Settings** `~/.dsh/settings.yaml`: `agent-default-model:
  {provider: kimi-coding, model: k3}`; `llm-pi-ai.providers.kimi-coding`;
  the NVIDIA 30-model free-tier profile.
- **Credential** `~/.dsh/.credentials.yaml`: record `llm-pi-ai/kimi-coding`,
  kind `grant`, type `oauth` (values differ per machine, structure matches).

## Parity check (both machines)

```bash
# dsh
dsh --profile web --dump-config | grep -A6 "subagent-kimi"                 # provider row present
grep -c "tool-subagent-kimi" ~/.dsh/.agent-presets/kimi/agent.cordis.yml   # → 1
cat ~/.dsh/settings.yaml                    # default kimi-coding/k3 + nvidia profile
ls ~/.dsh/skills/                           # 30 skills

# pi whisper server
systemctl --user is-active rust-whisper-server   # → active
curl http://localhost:10301/health               # → OK
sha256sum pi/speech-to-text/rust-whisper-server/ggml-base.bin   # 60ed5bc3…2efe

# pi voice client
pi list                                          # → npm:pi-voice-stt
cat ~/.pi/agent/stt.json                         # → provider.type "local"
command -v ffmpeg                                # → /usr/bin/ffmpeg
```

Outputs should match on both machines. Secrets differ, which is expected.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `profile ... does not exist` from `npm run dsh:setup` | Boot dsh once first (fresh machine step 1). |
| `NVIDIA (free tier)` missing in Models | Add `NVIDIA_API_KEY`, restart GUI. |
| `OAuth refresh failed … invalid grant` | Token lineage died. `npm run dsh:kimi-login` (or `kimi login` + `npm run dsh:bridge`). |
| Bridge version mismatch on `npm run dsh:setup` | dsh must be `0.1.1-rc.2` on that machine. |
| Skills missing in a session | `npm run skills:install`, then start a new session. |
| Whisper server down after repo update | Paths moved 2026-09-03; reinstall the systemd unit from the whisper SETUP.md and `systemctl --user daemon-reload`. |
| Whisper transcription slow on linden | Check it built with the cuda backend: the startup line in `server.log` prints the backend, and `nvidia-smi` should show the process. Rebuild via `run.sh` if it says cpu. |
| Voice recording fails, `ffmpeg` not found | The npm extension records with ffmpeg. `sudo apt install -y ffmpeg`. |
