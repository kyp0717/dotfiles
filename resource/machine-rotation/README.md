# Keeping the two machines in sync

You alternate between two computers, **woodlawn** and **linden**, swapping
roughly weekly. Both run the same two harnesses:

- **dsh** (DeepSeek Harness) with the Kimi Code integration
- **pi**, with voice input via the official `pi-voice-stt` npm extension and
  the local whisper speech-to-text server as its transcription backend

The repo is the single source of truth. Nothing on a machine is a copy of a
repo file by hand. Config is regenerated by scripts, and anything that must
stay per machine is listed below so you never sync the wrong thing.

See [`MACHINES.md`](MACHINES.md) for the per-machine facts (hardware, tuning,
hostnames).

---

## The mental model

**The repo is the recipe; the scripts bake the config.**

```
git clone dotfiles
  →  scripts/setup-packages.sh   # required apt packages (stow, ffmpeg, wl-clipboard, ...)
  →  scripts/setup-udev.sh       # udev rules (Yeti autosuspend defense)
  →  npm run dsh:setup          # writes ALL dsh harness config
  →  npm run skills:install     # dsh/skills → ~/.dsh/skills
  →  npm run dsh:kimi-login     # per-machine Kimi subscription credential
  →  stow -d ~/dotfiles pi                          # pi providers, skills, extensions
  →  resource/microphone/rust-whisper-server/run.sh # builds + runs whisper (see its SETUP.md)
```

Every step is idempotent. Re-running on a drifted machine brings it back.

## Fresh machine: full setup

Prerequisites: Node.js ≥ 18, git, Rust toolchain (for the whisper server),
and optionally the Kimi Code CLI (`kimi`) which powers `subagent_kimi`.

First, from the repo root, install the machine-level dependencies (both
scripts are idempotent and need sudo):

```bash
scripts/setup-packages.sh   # stow, ffmpeg, wl-clipboard, build deps, ...
scripts/setup-udev.sh       # Yeti mic autosuspend defense
```

`wl-clipboard` is not optional on Wayland: pi's copy/paste goes through
`wl-copy`/`wl-paste`, and without it every copy inside pi fails with
"Clipboard unavailable".

### dsh

1. Boot the pinned harness once so the profile initializes:
   `npx --yes @deepseek-ai/dsh@0.1.1-rc.2 --profile web`, then stop it.
2. `git clone git@github.com:kyp0717/dotfiles.git ~/dotfiles && cd ~/dotfiles`
3. `npm run dsh:setup` (writes the ACP bridge from `dsh/vendor/`, the profile
   patch, the `kimi` preset, and `settings.yaml` with default model
   `kimi-coding/k3` plus the NVIDIA free-tier profile)
4. `npm run dsh:kimi-login` (device-code login, per machine)
5. `npm run skills:install` (vendored skills → `~/.dsh/skills/`)
6. GUI → Settings → API keys: add `NVIDIA_API_KEY`, `DEEPSEEK_API_KEY`, and
   any pay-as-you-go Kimi keys you use
7. Restart the GUI and run the parity check below

Full detail and troubleshooting: [`dsh/docs/SETUP.md`](../../dsh/docs/SETUP.md).

### pi

1. Install pi itself (see pi's own docs) and sign in / set provider keys.
2. Build and start the whisper server via `run.sh` (it picks the backend by
   hostname; both machines are `cpu` since linden's GTX 1070 was replaced
   with an AMD RX 6700 XT, which whisper-rs cannot use), then register it as
   a systemd user service. Full procedure:
   [`resource/microphone/rust-whisper-server/SETUP.md`](../../resource/microphone/rust-whisper-server/SETUP.md).
3. On machines with fewer cores than woodlawn, set `WHISPER_THREADS` in the
   systemd unit (see `MACHINES.md`).
4. Install the voice client extension:
   `pi install npm:pi-voice-stt`, and write
   `~/.pi/agent/stt.json` with provider type `local`. (ffmpeg comes from
   `scripts/setup-packages.sh`.) Full procedure:
   [`resource/microphone/pi-voice-stt-setup.md`](../../resource/microphone/pi-voice-stt-setup.md).

pi skills come from two places:

1. **Canonical pstack** — vendored at `pi/.pi/pi-pstack/` (from npm
   `pi-pstack@0.1.0`; skills + subagent extension + poteto agents).
   Deployed by `stow pi` (→ `~/.pi/pi-pstack`) and declared in
   `~/.pi/agent/settings.json` as a local package
   (`packages: ["../../dotfiles/pi/.pi/pi-pstack"]` — copy
   `resource/pi-agent-settings.json` if the machine's settings lack it).
2. **Local skills** — `lesson-learned` and `graft` in
   `pi/.agents/skills/`, stowed to `~/.agents/skills/`:

```bash
stow -d ~/dotfiles pi
```

The two never overlap by name; skills resolve flat by name across all
discovery locations (first discovered wins), which is why the old
vendored pstack copy was removed when the package was adopted.

## Weekly swap routine

Before leaving machine A:

```bash
cd ~/dotfiles
git add -A && git commit -m "harness config update"   # if anything changed
git push
```

On machine B before working:

```bash
cd ~/dotfiles && git pull
npm run dsh:setup          # re-applies dsh config, idempotent
npm run skills:install     # refreshes ~/.dsh/skills from dsh/skills
stow -d ~/dotfiles pi                          # refreshes pi providers, skills, extensions
# whisper server: only rebuild if resource/microphone/ changed
# restart both harnesses, then run the parity check below
```

`npm run dsh:kimi-login` only when a token dies. The error "OAuth refresh
failed … invalid grant" means re-login.

While working on either machine: encode harness changes in this repo (script
or docs) and commit. Hand edits to `~/.dsh` do not sync. Secrets stay local:
a new API key on B is added in the GUI on B, and again on A when you return.

## Synced vs per machine

| Item | Synced via repo? | Where it lives |
|---|---|---|
| dsh setup/login/bridge scripts | yes | `dsh/scripts/` |
| Pinned dsh vendor tarballs | yes | `dsh/vendor/` |
| pi skills + extensions (local: `lesson-learned`, `graft`, `unslop.ts`) | yes, via stow | `pi/.agents/skills/`, `pi/.pi/` → `~/.agents/skills/`, `~/.pi/` |
| pi canonical pstack (vendored package, 44 skills + subagent extension) | yes, in git at `pi/.pi/pi-pstack/`, declared as local package | `~/.pi/pi-pstack` (symlink), declaration in settings.json |
| dsh skills (pstack-strict, 30) | yes, via `npm run skills:install` | `dsh/skills/` → `~/.dsh/skills/` |
| dsh profile patch, `kimi` preset, `settings.yaml` | yes, written by `npm run dsh:setup` | `~/.dsh/…` |
| pi whisper server source + setup doc | yes | `resource/microphone/rust-whisper-server/` |
| pi-voice-stt extension install (npm package) | no, per machine via `pi install` | `~/.pi/agent/npm/node_modules/pi-voice-stt`, settings.json |
| pi-voice-stt config (`stt.json`, provider `local`) | no, per machine | `~/.pi/agent/stt.json` |
| Whisper build (`target/`), logs | no, rebuilt per machine | `resource/microphone/rust-whisper-server/` (gitignored) |
| Whisper model `ggml-base.bin` (147 MB) | no, too big for git; rsync or re-download (checksum in its SETUP.md) | `resource/microphone/rust-whisper-server/` |
| Whisper systemd unit | content is in its SETUP.md; installed per machine | `~/.config/systemd/user/` |
| Kimi CLI login / OAuth / sessions | **per machine** | `~/.kimi-code/` |
| dsh subscription credential | **per machine**, via `npm run dsh:kimi-login` | `~/.dsh/.credentials.yaml` |
| Provider API keys | **per machine**, GUI settings | harness settings storage |
| Required apt packages (`stow`, `ffmpeg`, `wl-clipboard`, build deps) | **per machine**, installed by `scripts/setup-packages.sh` | apt |
| udev rules (Yeti autosuspend) | **per machine**, installed by `scripts/setup-udev.sh` | `/etc/udev/rules.d/` |

**Rule:** never copy `~/.kimi-code/`, credentials files, or API keys between
machines, and never commit them. Each machine authenticates once on its own.

## Parity check (both machines)

```bash
# dsh
dsh --profile web --dump-config | grep -A6 "subagent-kimi"                 # provider row present
grep -c "tool-subagent-kimi" ~/.dsh/.agent-presets/kimi/agent.cordis.yml   # → 1
cat ~/.dsh/settings.yaml                    # default kimi-coding/k3 + nvidia profile
ls ~/.dsh/skills/                           # 30 skills

# pi whisper server
systemctl --user is-active rust-whisper-server   # → active
grep ExecStart ~/.config/systemd/user/rust-whisper-server.service   # → ~/dotfiles/resource/microphone/...
curl http://localhost:10301/health               # → OK
sha256sum ~/dotfiles/resource/microphone/rust-whisper-server/ggml-base.bin   # 60ed5bc3…2efe

# pi skills + extensions (stow)
readlink ~/.pi/agent/extensions/unslop.ts          # → ~/dotfiles/pi/.pi/agent/extensions/unslop.ts
ls ~/.agents/skills/                               # stowed skill set + any local ones

# pi voice client
pi list                                          # → npm:pi-voice-stt
cat ~/.pi/agent/stt.json                         # → provider.type "local"
command -v ffmpeg                                # → /usr/bin/ffmpeg
```

Outputs should match on both machines. Secrets differ, which is expected.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `profile ... does not exist` from `npm run dsh:setup` | Boot dsh once first (fresh machine step 1). |
| `NVIDIA (free tier)` missing in Models | Add `NVIDIA_API_KEY`, restart GUI. |
| `OAuth refresh failed … invalid grant` | Token lineage died. `npm run dsh:kimi-login` (or `kimi login` + `npm run dsh:bridge`). |
| Bridge version mismatch on `npm run dsh:setup` | dsh must be `0.1.1-rc.2` on that machine. |
| Skills missing in a session | `npm run skills:install`, then start a new session. |
| Whisper server down after repo update | Paths moved 2026-09-03 into `pi/`, 2026-09-11 to `~/dotfiles`, 2026-09-11 out to `~/dotfiles/microphone/`, and later under `~/dotfiles/resource/microphone/`. Canonical path is `~/dotfiles/resource/microphone/rust-whisper-server/`; fix the systemd unit paths and `systemctl --user daemon-reload`. 2026-10-18 recurrence on linden: the unit had been recreated with the pre-`resource/` path because this README still showed it; README fixed. |
| Unit crash-loops, exit `status 209/STDOUT` | The unit's `WorkingDirectory`/`ExecStart`/log paths point at a location that does not exist on this machine. Canonical checkout is `~/dotfiles` on both machines; fix the paths, `daemon-reload`, restart. |
| `server.err.log` has `failed to open 'ggml-base.bin'` | The model (gitignored, 147 MB) did not survive a move. Re-download or rsync it; checksum in the whisper SETUP.md. |
| Voice dead in pi, mic records fine | The whisper server is the backend, not the mic. `systemctl --user status rust-whisper-server`; `curl -m 3 localhost:10301/health`. See the incident section in the whisper SETUP.md. |
| Whisper transcription slow on linden | It runs on CPU (AMD 6700 XT is not usable by whisper-rs). Tune `WHISPER_THREADS` in the systemd unit; the startup line in `server.log` prints the backend. |
| Voice recording fails, `ffmpeg` not found | The npm extension records with ffmpeg. `sudo apt install -y ffmpeg`. |
