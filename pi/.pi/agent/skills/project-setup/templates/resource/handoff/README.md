# Handoff notes

Continuation briefs: what the next session, or another machine, needs
to know to pick up this project safely.

One file per topic, named `YYYY-MM-DD-<topic>.md`. A new session reads
the newest datestamp first. Retire a unit when its items are done
rather than appending forever — many small files, not one growing log.

Good candidates for handoff units:

- Current live state and how to run the project end to end.
- Pending follow-ups and where they were left.
- Anything dangerous to touch and the safe path around it.
- Per-machine facts and recreate steps (kept out of tracked code).
